# 14. Задачи уровня junior

> ⏱ **~60 минут** на проработку · 5 задач по 10–15 минут · грейд `[J]`

Задачи, которые дают на секции live-coding для junior. Проверяют не алгоритмическую подготовку, а базовую грамотность: работу со строками, слайсами и картами, обработку граничных случаев и умение проговаривать решение вслух.

Все решения ниже проверены: компилируются, проходят `go vet` и `gofmt`.

---

## Как оценивают live-coding

Интервьюер смотрит не только на работающий код. Порядок важности примерно такой:

1. **Уточнил ли требования.** Что делать с пустым входом? С кириллицей? Регистр важен? Один вопрос до начала стоит десяти правок после.
2. **Проговаривает ли решение.** Молчаливое написание кода не даёт понять ход мысли; если решение неверное, помочь тоже нечем.
3. **Граничные случаи.** Пустой слайс, `nil`, один элемент, повторы, юникод.
4. **Идиоматичность.** `range` вместо счётчика, `strings.Builder` вместо конкатенации, готовое из стандартной библиотеки вместо велосипеда.
5. **Тестируемость.** Хорошо, если после решения человек сам говорит, какие случаи покрыл бы тестами.

Скорость важна меньше всего. Кандидат, который за десять минут уточнил требования и написал корректное решение, сильнее того, кто за три минуты выдал код, падающий на кириллице.

### Задача 1: развернуть строку `[J]` · ~10 мин

**Условие.** Напишите функцию `Reverse(s string) string`, возвращающую строку задом наперёд.

**На что смотрит интервьюер.**

- Спросит ли кандидат про юникод — это главная проверка задачи.
- Знает ли разницу между `[]byte` и `[]rune`.
- Обработает ли пустую строку.
- Обойдётся ли без лишних аллокаций внутри цикла.

**Решение.**

```go
func Reverse(s string) string {
	r := []rune(s)
	for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
		r[i], r[j] = r[j], r[i]
	}
	return string(r)
}
```

Проверено: `Reverse("привет")` даёт `тевирп`, `Reverse("go")` даёт `og`. Пустая строка возвращается пустой без отдельной обработки — цикл просто не выполняется.

**Типичные ошибки.**

- Работа с `s[i]` побайтно — кириллица рассыплется на половинки символов.
- Сборка результата конкатенацией в цикле: квадратичная сложность.
- Отдельная проверка на пустую строку, которая не нужна.
- Использование `len(s)` как числа символов.

**Развитие.** «А если в строке эмодзи с модификаторами?» — тогда `[]rune` тоже недостаточно, нужны графемные кластеры, которых в стандартной библиотеке нет. Ожидается не решение, а понимание, что проблема существует.

### Задача 2: проверить палиндром `[J]` · ~12 мин

**Условие.** Напишите `IsPalindrome(s string) bool`. Регистр и знаки препинания игнорировать. Пример: «А роза упала на лапу Азора» — палиндром.

**На что смотрит интервьюер.**

- Уточнит ли правила: что считать «знаками препинания», важен ли регистр.
- Догадается ли использовать `unicode.IsLetter` вместо перечисления символов.
- Не станет ли разворачивать строку и сравнивать — это лишняя аллокация.

**Решение.**

```go
func IsPalindrome(s string) bool {
	var r []rune
	for _, c := range strings.ToLower(s) {
		if unicode.IsLetter(c) || unicode.IsDigit(c) {
			r = append(r, c)
		}
	}
	for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
		if r[i] != r[j] {
			return false
		}
	}
	return true
}
```

Проверено: фраза про розу даёт `true`, «привет» — `false`.

**Типичные ошибки.**

- Сравнение с развёрнутой копией — работает, но выделяет память зря.
- Фильтрация только пробелов, без знаков препинания.
- `strings.ToLower` внутри цикла на каждом символе.
- Побайтовый обход.

**Развитие.** «Как обойтись без выделения слайса рун?» — двумя указателями по исходной строке с пропуском неподходящих символов; сложнее, но без аллокаций. Просят обычно только описать подход.

### Задача 3: топ-N частых слов `[J]` · ~15 мин

**Условие.** По тексту вернуть N самых частых слов. При равной частоте — по алфавиту.

**На что смотрит интервьюер.**

- Знает ли идиому `freq[word]++` без проверки существования ключа.
- Помнит ли, что порядок обхода карты случаен, и сортирует явно.
- Реализует ли вторичную сортировку по алфавиту — без неё результат нестабилен.
- Обработает ли `n` больше числа уникальных слов.

**Решение.**

```go
type WordCount struct {
	Word  string
	Count int
}

func TopWords(text string, n int) []WordCount {
	freq := make(map[string]int)
	for _, w := range strings.Fields(strings.ToLower(text)) {
		w = strings.Trim(w, ".,!?;:—")
		if w != "" {
			freq[w]++
		}
	}

	out := make([]WordCount, 0, len(freq))
	for w, c := range freq {
		out = append(out, WordCount{w, c})
	}
	sort.Slice(out, func(i, j int) bool {
		if out[i].Count != out[j].Count {
			return out[i].Count > out[j].Count
		}
		return out[i].Word < out[j].Word
	})

	if n > len(out) {
		n = len(out)
	}
	return out[:n]
}
```

Проверено на «мама мыла раму. Мама мыла окно!» с `n=2`: `[{мама 2} {мыла 2}]` — обратите внимание, что при равной частоте порядок алфавитный и стабильный.

**Типичные ошибки.**

- Возврат результата без сортировки — «работает» на одном запуске и ломается на следующем.
- Отсутствие вторичного критерия: тест то проходит, то нет.
- Паника при `n > len(out)`.
- Проверка `if _, ok := freq[w]; !ok { freq[w] = 0 }` перед увеличением — лишняя.

**Развитие.** «А если текст не помещается в память?» — потоковое чтение построчно плюс куча фиксированного размера вместо полной сортировки. «Как ускорить?» — `container/heap` даёт O(n log k) вместо O(n log n).

### Задача 4: убрать дубликаты, сохранив порядок `[J]` · ~10 мин

**Условие.** Из слайса удалить повторы, сохранив порядок первого появления.

**На что смотрит интервьюер.**

- Использует ли карту как множество, а не вложенный цикл.
- Знает ли идиому `map[T]struct{}` вместо `map[T]bool`.
- Резервирует ли ёмкость.
- Догадается ли писать в тот же массив через `in[:0]`.

**Решение.**

```go
func Unique[T comparable](in []T) []T {
	seen := make(map[T]struct{}, len(in))
	out := in[:0]
	for _, v := range in {
		if _, ok := seen[v]; ok {
			continue
		}
		seen[v] = struct{}{}
		out = append(out, v)
	}
	return out
}
```

Проверено: `[1 2 2 3 1]` даёт `[1 2 3]`, работает и для строк.

Приём `out := in[:0]` переиспользует исходный массив — новых аллокаций нет. **Важно предупредить об этом интервьюера**: функция портит входной слайс, и это осознанный компромисс. Если такое недопустимо, пишут `make([]T, 0, len(in))`.

**Типичные ошибки.**

- Вложенный цикл — O(n²) вместо O(n).
- `map[T]bool` вместо `struct{}` — работает, но тратит память.
- Молчаливая порча входных данных без предупреждения.
- Ограничение `[]int` там, где годится дженерик.

**Развитие.** «А если тип несравним, например слайсы?» — тогда карта не подойдёт: нужна нормализация в строку или попарное сравнение.

### Задача 5: слить два отсортированных слайса `[J]` · ~12 мин

**Условие.** Даны два отсортированных слайса чисел. Вернуть один отсортированный, содержащий все элементы.

**На что смотрит интервьюер.**

- Реализует ли слияние двумя указателями за один проход, а не конкатенацию с сортировкой.
- Обработает ли `nil` и пустые слайсы.
- Не забудет ли дописать остаток длинного слайса.
- Зарезервирует ли ёмкость.

**Решение.**

```go
func MergeSorted(a, b []int) []int {
	out := make([]int, 0, len(a)+len(b))
	i, j := 0, 0
	for i < len(a) && j < len(b) {
		if a[i] <= b[j] {
			out = append(out, a[i])
			i++
		} else {
			out = append(out, b[j])
			j++
		}
	}
	out = append(out, a[i:]...)
	return append(out, b[j:]...)
}
```

Проверено: `[1 3 5]` и `[2 4]` дают `[1 2 3 4 5]`; `nil` с `[1]` в любом порядке даёт `[1]`.

Хвосты дописываются через `a[i:]...` без дополнительных условий: если элементы кончились, срез пустой и `append` ничего не делает. Это избавляет от двух `if` и типичной ошибки «забыл остаток».

**Типичные ошибки.**

- `append(a, b...)` с последующей сортировкой — O(n log n) вместо O(n) и порча слайса `a`.
- Забытый остаток одного из слайсов.
- Отдельные ветки для `nil` — не нужны, `len(nil)` равен нулю.
- Строгое `<` вместо `<=`: устойчивость нарушится, если элементы равны и важен порядок источников.

**Развитие.** «А если слайсов K?» — попарное слияние даёт O(nK), куча — O(n log K). «А если они не помещаются в память?» — внешняя сортировка слиянием, классика для больших файлов.

## Чек-лист перед секцией

Проверьте, что можете без подсказок:

- развернуть строку и посчитать символы с учётом юникода;
- посчитать частоту через карту и стабильно отсортировать результат;
- убрать дубликаты за один проход;
- слить отсортированные последовательности двумя указателями;
- назвать граничные случаи любой из этих задач до написания кода.

И главное: **проговаривайте вслух**. Формулировка «сначала уточню: строка может содержать кириллицу?» стоит дороже, чем правильный код молча.
