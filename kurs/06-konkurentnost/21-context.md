# 21. `context`: отмена и дедлайны

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Пользователь закрыл вкладку — обработчик запроса должен остановиться, а вместе с ним и все горутины, которые он породил: запрос к базе, поход в соседний сервис, чтение файла. `context` — стандартный механизм, передающий сигнал отмены по всей цепочке вызовов. Без него горутины продолжают работу на никому не нужный результат.

## Что такое контекст

`context.Context` — интерфейс с четырьмя методами, из которых на практике нужны два:

- **`Done()`** — канал, который закрывается при отмене;
- **`Err()`** — причина отмены.

Идея вся в первом: закрытие канала оповещает **всех** ожидающих сразу — приём из статьи 18.

Корневой контекст создают функцией `context.Background()` — он никогда не отменяется. От него порождают производные.

## Отмена по таймауту

```go
ctx, cancel := context.WithTimeout(context.Background(), 50*time.Millisecond)
defer cancel()
```

Функция, умеющая отменяться, ждёт сразу два события:

```go
func slowWork(ctx context.Context, d time.Duration) (string, error) {
	select {
	case <-time.After(d):
		return "готово", nil
	case <-ctx.Done():
		return "", ctx.Err()
	}
}
```

```
 context deadline exceeded
```

Работа на 500 мс прервана через 50. Причина различима программно:

```go
errors.Is(ctx.Err(), context.DeadlineExceeded)     // true
```

Две стандартные причины: `context.DeadlineExceeded` (вышло время) и `context.Canceled` (отменили явно). Проверяют их через `errors.Is` — правило из статьи 13 работает и здесь.

Есть и `context.WithDeadline` — то же самое, но с абсолютным моментом времени вместо длительности.

## Явная отмена

`context.WithCancel` даёт контекст, отменяемый вручную. Так останавливают пул воркеров:

```go
ctx, cancel := context.WithCancel(context.Background())

for i := 1; i <= 3; i++ {
	wg.Add(1)
	go worker(ctx, i, &wg, out)
}

time.Sleep(30 * time.Millisecond)
cancel()
wg.Wait()
```

```go
func worker(ctx context.Context, id int, wg *sync.WaitGroup, out chan<- string) {
	defer wg.Done()
	for {
		select {
		case <-ctx.Done():
			out <- fmt.Sprintf("воркер %d остановлен: %v", id, ctx.Err())
			return
		case <-time.After(10 * time.Millisecond):
			// полезная работа
		}
	}
}
```

```
остановлено воркеров: 3
```

Один вызов `cancel()` остановил все три горутины. Это штатный способ борьбы с утечкой горутин из статьи 19.

## `cancel` вызывают всегда

Самое частое замечание на ревью:

```go
ctx, _ := context.WithTimeout(context.Background(), time.Second)
```

```
lc/main.go:9:7: the cancel function returned by context.WithTimeout should be
called, not discarded, to avoid a context leak
```

`go vet` ловит это сам. Почему важно: контекст с таймаутом заводит таймер и регистрируется у родителя. Без `cancel()` эти ресурсы живут до срабатывания таймаута, даже если работа давно закончилась.

Правило: **`defer cancel()` сразу после создания**, всегда. Повторный вызов безопасен, так что перестраховаться нельзя.

## Дерево контекстов

Производные контексты образуют дерево, и отмена распространяется **сверху вниз**:

```go
parent, pcancel := context.WithCancel(context.Background())
child, ccancel := context.WithTimeout(parent, time.Hour)
defer ccancel()

pcancel()
<-child.Done()
fmt.Println(child.Err())     // context canceled
```

Потомок с часовым таймаутом отменился мгновенно вместе с родителем. Благодаря этому отмена HTTP-запроса на верхнем уровне доходит до запроса к базе в глубине стека — при условии, что контекст передавался.

Обратное неверно: отмена потомка не трогает родителя.

## Значения в контексте

`context.WithValue` кладёт в контекст произвольную пару:

```go
type ctxKey string
const userKey ctxKey = "user"

ctx := context.WithValue(context.Background(), userKey, "Алия")

if u, ok := ctx.Value(userKey).(string); ok {
	// ...
}
```

Две обязательные детали:

**Ключ — свой неэкспортируемый тип**, а не строка. Иначе два пакета с ключом `"user"` перезапишут друг друга. Собственный тип делает коллизию невозможной.

**Значение достают приведением типа** — контекст хранит `any`, со всеми последствиями из статьи 12.

Чего в контекст класть **нельзя**: параметры функции. Он предназначен для данных, сквозных для всего запроса, — идентификатор трассировки, информация об аутентификации, локаль. Всё, что нужно конкретной функции для работы, передают обычными аргументами: иначе компилятор перестаёт вам помогать.

## Соглашения

Устоялись жёстко, отступать от них не стоит:

1. **`ctx` — первый параметр функции**, имя всегда `ctx`.
2. **Контекст не хранят в структуре.** Он описывает жизненный цикл вызова, а не объекта. Исключения редки и обычно связаны с долгоживущими сервисами.
3. **Не передавайте `nil`-контекст.** Если не знаете, какой взять, — `context.Background()`; в заготовках, где контекст появится позже, — `context.TODO()`.
4. **Функция, вызывающая внешние сервисы, обязана принимать контекст** и передавать его дальше. Разрыв цепочки в одном месте делает отмену бесполезной.

Стандартная библиотека следует тем же правилам: `http.NewRequestWithContext`, `db.QueryContext`, `exec.CommandContext`.

## Что запомнить

- `context` передаёт сигнал отмены по цепочке вызовов; основа — закрытие канала `Done()`.
- `context.Background()` — корень; производные создают `WithTimeout`, `WithDeadline`, `WithCancel`, `WithValue`.
- Отменяемая функция ждёт `ctx.Done()` в `select` наряду с полезной работой.
- Причину различают через `errors.Is`: `DeadlineExceeded` или `Canceled`.
- `defer cancel()` пишут всегда — иначе утечка таймера; `go vet` это проверяет.
- Отмена распространяется от родителя к потомкам, но не наоборот.
- Ключ для `WithValue` — свой неэкспортируемый тип; значение достают приведением.
- В контекст кладут сквозные данные запроса, а не параметры функции.
- `ctx` — первый параметр, в структурах не хранится, `nil` не передаётся.

## Практика

**1. Таймаут.** Напишите функцию, которая «работает» 300 мс и умеет отменяться. Вызовите её с контекстами на 100 мс и на 500 мс. Готово, когда оба исхода обработаны и различимы через `errors.Is`.

**2. Остановка воркеров.** Запустите пять воркеров, работающих в бесконечном цикле, и остановите их одним `cancel()`. Проверьте `runtime.NumGoroutine()` до и после. Готово, когда число вернулось к исходному.

**3. Утечка контекста.** Напишите код, отбрасывающий `cancel` через `_`, и найдите замечание `go vet`. Готово, когда понимаете, какой ресурс утекает.

**4. Дерево отмены.** Постройте цепочку из трёх контекстов, отмените средний и проверьте состояние всех трёх. Готово, когда можете предсказать результат до запуска.

**5. Значение запроса.** Реализуйте передачу идентификатора запроса через контекст: функция верхнего уровня кладёт его, функция в глубине достаёт и печатает. Используйте свой тип ключа. Готово, когда идентификатор доходит через три уровня вызовов.
