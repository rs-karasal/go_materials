# 6. Массивы и слайсы: устройство, `len`, `cap`, `append`

> ⏱ **~60 минут** · теория 25 мин · практика 35 мин

Слайс — самый используемый тип в Go и одновременно источник самых обидных ошибок. Выглядит он как обычный динамический массив, но устроен иначе, и незнание внутренностей приводит к багам, которые проявляются не сразу. Разберём устройство до конца — эта статья окупится многократно.

## Массив: фиксированный размер и значение

```go
arr := [3]int{1, 2, 3}
```

Длина — **часть типа**: `[3]int` и `[4]int` несовместимы. Отсюда главное следствие: массив — это значение, и при передаче он **копируется целиком**.

```go
func modifyArray(a [3]int) { a[0] = 100 }

modifyArray(arr)
fmt.Println(arr)      // [1 2 3] — не изменился
```

Из-за фиксированной длины массивы напрямую почти не используют. Они нужны как фундамент для слайсов.

## Слайс: окно в массив

```go
sl := []int{1, 2, 3}
func modifySlice(s []int) { s[0] = 100 }

modifySlice(sl)
fmt.Println(sl)       // [100 2 3] — изменился
```

Разница в квадратных скобках без числа — и в поведении. Почему так?

Слайс — это структура из **трёх полей**: указатель на массив с данными, длина (`len`) и вместимость (`cap`). При передаче в функцию копируется сама структура — три машинных слова, — но указатель в копии тот же. Отсюда и правка исходных данных.

- **`len`** — сколько элементов доступно сейчас.
- **`cap`** — сколько помещается в выделенной памяти от начала слайса до конца массива.

```go
var s []int
fmt.Printf("%v len=%d cap=%d nil=%t\n", s, len(s), cap(s), s == nil)
```

```
[] len=0 cap=0 nil=true
```

Нулевое значение слайса — `nil`, но с ним можно работать: `len`, `range` и `append` на `nil`-слайсе корректны. Это тот самый принцип осмысленного нулевого значения из статьи 3. Проверять `if s != nil` перед добавлением не нужно.

## `append` и рост вместимости

```go
s = append(s, 1)
```

`append` **возвращает новый слайс** — его результат обязательно присваивают. Если места хватает, элемент кладётся в существующий массив. Если нет — выделяется новый, больший, данные копируются, а старый отправляется сборщику мусора.

Посмотрим, как растёт `cap`:

```
рост cap: 1 -> 2 -> 4 -> 8 -> 16 -> 32
```

Удвоение (на больших размерах коэффициент уменьшается). Значит, добавление N элементов по одному вызывает несколько перевыделений с копированием.

Если размер известен заранее, его резервируют:

```go
s := make([]int, 0, 100)     // len=0, cap=100
```

`make` принимает тип, длину и необязательную вместимость. Две частые формы:

- `make([]int, 5)` — пять нулей, `len=5`;
- `make([]int, 0, 5)` — пустой слайс с запасом, `len=0`, `cap=5`.

Разница существенная: в первом случае `append` добавит **шестой** элемент, а не заполнит первый.

## Срезы разделяют память

Здесь начинается самое важное.

```go
base := []int{1, 2, 3, 4, 5}
part := base[1:3]
fmt.Printf("%v len=%d cap=%d\n", part, len(part), cap(part))
```

```
[2 3] len=2 cap=4
```

`len` равен двум, а `cap` — четырём: от позиции 1 до конца исходного массива. Новый слайс **не копирует данные**, он смотрит в тот же массив.

```go
part[0] = 99
fmt.Println(base)     // [1 99 3 4 5]
```

Правка через срез изменила оригинал. Это ожидаемо, но следующий эффект — уже нет:

```go
part = append(part, 777)
fmt.Println(base)     // [1 99 3 777 5]
```

`append` увидел, что `cap` позволяет, и записал 777 **поверх четвёртого элемента исходного слайса**. Никакого предупреждения. Функция, которая принимает слайс и делает `append`, может незаметно испортить данные вызывающего кода — классический баг, который ищут часами.

Два способа защититься.

**Копия** — когда данные должны быть независимыми:

```go
safe := make([]int, len(base))
copy(safe, base)
```

`copy` копирует минимум из длин источника и приёмника, возвращая число скопированных элементов.

**Ограничение вместимости** — трёхиндексный срез `base[1:3:3]`:

```go
full := base[1:3:3]      // len=2, cap=2
full = append(full, 42)  // cap исчерпан -> новый массив
```

Теперь `append` вынужден выделить новую память, и оригинал в безопасности. Приём стоит применять, когда возвращаете срез внутренних данных наружу.

## `range` копирует значения

```go
for i, v := range base {
	v = v * 10        // меняем копию
}
fmt.Println(base)     // не изменился
```

Переменная `v` — копия элемента. Чтобы изменить сам элемент, обращайтесь по индексу: `base[i] = base[i] * 10`.

Особенно коварно это со структурами: `for _, u := range users { u.Active = true }` не изменит ни одного пользователя.

## Многомерность

Отдельного типа для матрицы нет — есть слайс слайсов, и каждую строку создают отдельно:

```go
matrix := make([][]int, 2)
for i := range matrix {
	matrix[i] = make([]int, 3)
}
matrix[1][2] = 7      // [[0 0 0] [0 0 7]]
```

Строки при этом независимы и могут быть разной длины.

## Выход за границы

Проверяется в рантайме, нарушение даёт панику:

```
panic: runtime error: index out of range [5] with length 3
```

Компилятор ловит только очевидные случаи с константным индексом. Обращение по вычисленному индексу проверяется при выполнении.

## Что запомнить

- Длина массива — часть типа; массив копируется при передаче.
- Слайс — структура из указателя, `len` и `cap`; копия слайса указывает на те же данные.
- Нулевое значение слайса — `nil`, но `len`, `range` и `append` с ним работают.
- `append` возвращает новый слайс, его результат нужно присваивать.
- При нехватке места массив перевыделяется с удвоением; известный размер резервируют через `make`.
- `make([]int, 5)` и `make([]int, 0, 5)` — разные вещи: длина против запаса.
- Срез разделяет память с исходным слайсом; `append` в срез может незаметно перезаписать соседние элементы.
- Независимость данных даёт `copy` или трёхиндексный срез `s[a:b:b]`.
- `range` отдаёт копию значения — изменить элемент можно только по индексу.

## Практика

**1. Значение против ссылки.** Напишите две функции, изменяющие первый элемент: одна принимает `[3]int`, другая `[]int`. Вызовите обе и объясните разницу в результате. Готово, когда можете объяснить её через устройство типов.

**2. Наблюдение за ростом.** Заведите слайс через `make([]int, 0, 1)` и в цикле из 50 добавлений печатайте `len` и `cap` только в моменты их изменения. Готово, когда видите последовательность роста и понимаете её.

**3. Резерв.** Замерьте время заполнения слайса миллионом элементов двумя способами: с `make([]int, 0)` и с `make([]int, 0, 1_000_000)`. Готово, когда есть два числа и объяснение разницы.

**4. Ловушка среза.** Воспроизведите ситуацию, где `append` в срез портит исходный слайс. Затем почините двумя способами — через `copy` и через трёхиндексный срез. Готово, когда оба варианта оставляют оригинал нетронутым.

**5. Фильтрация без выделений.** Напишите функцию, удаляющую из слайса чисел все отрицательные, **не выделяя новый слайс** (подсказка: `s[:0]` даёт пустой слайс поверх той же памяти). Готово, когда функция работает и вы понимаете, почему это безопасно.
