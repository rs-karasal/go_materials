# 25. `encoding/json` и работа с файлами

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Читать конфигурацию, разбирать ответ API, сохранять состояние на диск — работа, которая есть почти в любой программе. В Go для этого не нужны внешние библиотеки: `encoding/json` и `os` покрывают подавляющее большинство случаев. Разберём их вместе с тегами структур — механизмом, который связывает поля Go с полями JSON.

## Сериализация

```go
type Task struct {
	ID    int    `json:"id"`
	Title string `json:"title"`
	Done  bool   `json:"done"`
}

b, err := json.MarshalIndent(t, "", "  ")
```

```json
{
  "id": 1,
  "title": "написать статью",
  "done": false
}
```

`json.Marshal` возвращает компактный JSON, `MarshalIndent` — форматированный.

Строка в обратных кавычках после типа поля — **тег структуры**. Без него имена в JSON совпадали бы с именами полей (`ID`, `Title`), что не соответствует общепринятому стилю.

Важное ограничение: **сериализуются только экспортированные поля**. Поле с маленькой буквы `json` не увидит вовсе, и тег ему не поможет. Это следствие правил видимости из статьи 15 — пакет `json` работает через рефлексию и просто не имеет доступа к приватным полям.

## Теги

Основные варианты:

```go
type Task struct {
	ID       int        `json:"id"`
	Due      *time.Time `json:"due,omitempty"`
	Internal string     `json:"-"`
	Tags     []string   `json:"tags,omitempty"`
}
```

| Тег | Что делает |
|---|---|
| `json:"id"` | имя поля в JSON |
| `json:"-"` | никогда не сериализовать |
| `json:",omitempty"` | пропустить, если значение нулевое |
| `json:"id,string"` | число в JSON как строка |

`omitempty` считает «пустыми» нулевые значения: `0`, `""`, `false`, `nil`, пустой слайс. Отсюда следствие: поле `Count int` со значением 0 исчезнет из вывода. Если ноль — значимое значение, берите указатель `*int` (приём из статьи 9) — тогда «не задано» и «задано нулём» различаются.

В примере поле `Internal` не попало в вывод из-за `json:"-"`, а `Due` и `Tags` — из-за `omitempty`.

## Разбор

```go
var parsed Task
err := json.Unmarshal([]byte(raw), &parsed)
```

```
{ID:2 Title:из JSON Done:true Due:<nil> Internal: Tags:[go доки]}
```

Три вещи, которые надо знать.

**Передавайте указатель.** `Unmarshal` заполняет переданную структуру, значит, ему нужен адрес. Без `&` вернётся ошибка.

**Лишние поля игнорируются.** В примере в JSON было `"extra":"игнор"` — оно просто отброшено. Если нужен строгий разбор, у `json.Decoder` есть `DisallowUnknownFields()`.

**Отсутствующие поля остаются нулевыми.** Отличить «поле не пришло» от «пришло нулевым» позволяет только указатель.

Ошибки разбора информативны:

```
json: cannot unmarshal string into Go struct field Task.id of type int
```

Указано и поле, и ожидаемый тип. Тип ошибки различим через `errors.As` — правило из статьи 13:

```go
var typeErr *json.UnmarshalTypeError
errors.As(err, &typeErr)     // true
```

## Данные неизвестной формы

Когда структуры нет, разбирают в `map[string]any`:

```go
var loose map[string]any
json.Unmarshal([]byte(raw), &loose)
fmt.Printf("%v (%T)\n", loose["id"], loose["id"])
```

```
2 (float64)
```

Обратите внимание: **число стало `float64`**, а не `int`. В JSON один числовой тип, и `encoding/json` отображает его так по умолчанию. Приведение `loose["id"].(int)` вызовет панику — классическая ошибка.

Отсюда вывод: пользуйтесь `map[string]any` только когда формы данных действительно нет. Структура с тегами даёт правильные типы и проверку бесплатно — со всеми оговорками про `any` из статьи 12.

## Файлы: простой путь

```go
os.WriteFile(path, data, 0o644)
data, err := os.ReadFile(path)
```

Обе функции работают с файлом целиком. Число `0o644` — права доступа в восьмеричной записи: владелец пишет и читает, остальные читают.

Отсутствие файла — обычная ошибка, распознаваемая через `errors.Is`:

```go
_, err = os.ReadFile("нет.json")
errors.Is(err, os.ErrNotExist)     // true
```

Полезные функции: `os.MkdirAll` (создать дерево папок), `os.Remove` / `os.RemoveAll`, `os.MkdirTemp` (временная папка — удобно в тестах), `os.Stat` (сведения о файле).

## Файлы: потоковый путь

Когда файл большой, целиком его в память не читают. Построчное чтение — через `bufio.Scanner`:

```go
f, err := os.Open(path)
if err != nil {
	return err
}
defer f.Close()

sc := bufio.NewScanner(f)
for sc.Scan() {
	line := sc.Text()
	// ...
}
if err := sc.Err(); err != nil {
	return err
}
```

Две детали, которые пропускают.

**`sc.Err()` после цикла обязательна.** Цикл `Scan()` завершается и при конце файла, и при ошибке чтения — без проверки вы примете сбой за нормальное завершение.

**У сканера есть предел длины строки** (64 КБ по умолчанию). Для длинных строк буфер увеличивают через `sc.Buffer(...)`.

Запись симметрична — через `bufio.Writer`:

```go
w := bufio.NewWriter(f)
fmt.Fprintf(w, "строка %d\n", i)
if err := w.Flush(); err != nil {
	return err
}
```

**`Flush` обязателен.** `bufio.Writer` копит данные в памяти, и без сброса последняя порция не дойдёт до диска. Это самая частая ошибка при работе с буферизованной записью.

## Потоковый JSON

`Encoder` и `Decoder` работают с `io.Writer` и `io.Reader` — то есть с чем угодно из статьи 11:

```go
enc := json.NewEncoder(os.Stdout)
enc.SetIndent("", "  ")
enc.Encode(v)

dec := json.NewDecoder(resp.Body)
dec.Decode(&result)
```

Так избегают промежуточного слайса байтов. Для HTTP-ответов (статья 26) это стандартный способ: `json.NewDecoder(resp.Body).Decode(&v)`.

## Что запомнить

- Сериализуются только экспортированные поля — приватные `json` не видит.
- Теги задают имя (`json:"id"`), пропуск (`json:"-"`) и `omitempty`.
- `omitempty` убирает нулевые значения; чтобы различать «ноль» и «не задано», берите указатель.
- `Unmarshal` требует указателя; лишние поля игнорируются, отсутствующие остаются нулевыми.
- Числа в `map[string]any` приходят как `float64`, а не `int`.
- `os.ReadFile` / `os.WriteFile` — для небольших файлов; отсутствие файла проверяют через `errors.Is(err, os.ErrNotExist)`.
- Большие файлы читают `bufio.Scanner`; после цикла обязательна проверка `sc.Err()`.
- При записи через `bufio.Writer` обязателен `Flush()`.
- `json.NewDecoder(r).Decode(&v)` работает с любым `io.Reader` — так разбирают HTTP-ответы.

## Практика

**1. Туда и обратно.** Опишите структуру «пользователь» с тегами, сериализуйте её в файл и прочитайте обратно. Готово, когда данные совпадают до и после.

**2. Теги.** Добейтесь, чтобы одно поле не попадало в JSON, второе исчезало при нулевом значении, а третье называлось в camelCase. Готово, когда вывод соответствует ожиданиям для заполненной и пустой структуры.

**3. Ноль против «не задано».** Опишите структуру с полем `Count int` и `Count *int`. Сериализуйте обе при нулевом значении и сравните. Готово, когда понимаете, зачем нужен указатель.

**4. Разбор чужого JSON.** Возьмите JSON, где есть лишние поля, отсутствует одно из ваших и одно поле неверного типа. Разберите его, обработав ошибку через `errors.As`. Готово, когда программа сообщает, какое именно поле не сошлось.

**5. Большой файл.** Сгенерируйте файл на 100 000 строк, посчитайте в нём строки, содержащие заданное слово, через `bufio.Scanner`. Проверьте `sc.Err()`. Затем сравните время с `os.ReadFile` и разбиением строкой. Готово, когда есть два числа.
