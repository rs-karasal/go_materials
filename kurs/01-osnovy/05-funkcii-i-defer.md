# 5. Функции: несколько возвращаемых значений, замыкания, `defer`

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Функции в Go устроены обычно, но с двумя особенностями, определяющими весь стиль языка: они возвращают несколько значений и умеют откладывать выполнение через `defer`. Из первого выросла вся модель обработки ошибок, из второго — способ гарантированно освобождать ресурсы.

## Объявление

```go
func divide(a, b int) (int, error) {
	if b == 0 {
		return 0, fmt.Errorf("деление на ноль")
	}
	return a / b, nil
}
```

Тип пишется **после** имени — как и в объявлении переменных. Подряд идущие параметры одного типа объединяются: `(a, b int)` вместо `(a int, b int)`.

## Несколько возвращаемых значений

Ключевая особенность. Функция возвращает результат **и** ошибку, а не одно вместо другого:

```go
if q, err := divide(10, 2); err == nil {
	fmt.Println("частное:", q)
}

if _, err := divide(1, 0); err != nil {
	fmt.Println("ошибка:", err)      // деление на ноль
}
```

Здесь работает форма `if` с инструкцией из прошлой статьи — и это самая частая конструкция в коде на Go.

Именно поэтому в языке нет исключений. Ошибка — обычное второе значение, её видно в сигнатуре и невозможно случайно пропустить: получив два значения, вы обязаны что-то сделать с обоими. Подробно — в статье 13.

Возвращаемые значения можно **именовать**:

```go
func minMax(nums []int) (min, max int) {
	min, max = nums[0], nums[0]
	for _, n := range nums {
		if n < min { min = n }
		if n > max { max = n }
	}
	return          // «голый» return: вернутся min и max
}
```

Именованные результаты — обоюдоострый инструмент. Они документируют смысл возвращаемых значений (что важно, когда их три-четыре одинакового типа), но «голый» `return` в длинной функции читается плохо: непонятно, что именно вернулось. Правило: **именуйте для документации, но пишите `return` явно**. Исключение — изменение ошибки в `defer`, о нём ниже.

## Переменное число аргументов

```go
func sum(nums ...int) int {
	total := 0
	for _, n := range nums {
		total += n
	}
	return total
}

sum(1, 2, 3)             // 6
sum([]int{4, 5}...)      // 9 — распаковка слайса
```

Внутри функции `nums` — обычный слайс. Троеточие после слайса при вызове распаковывает его в отдельные аргументы. Так устроен, например, `fmt.Println`.

## Функции как значения

Функция в Go — полноценное значение: её можно присвоить переменной, передать аргументом и вернуть из другой функции.

**Замыкание** — функция, захватившая переменные из окружения:

```go
func counter() func() int {
	count := 0
	return func() int {
		count++
		return count
	}
}

next := counter()
fmt.Println(next(), next(), next())     // 1 2 3
```

Переменная `count` живёт, пока жива вернувшаяся функция. Сборщик мусора сам решает, когда её освободить, — за временем жизни следить не нужно.

## `defer`

Откладывает вызов до момента выхода из функции — **в любом случае**: через `return`, через панику, из любой ветви.

```go
f, err := os.Open(name)
if err != nil {
	return err
}
defer f.Close()
```

Открыли — тут же написали, как закрыть. Дальше можно делать `return` откуда угодно: файл закроется. Сравните с языками, где для этого нужен `try/finally` или блок `with`, — здесь освобождение стоит рядом с захватом, и его не приходится искать глазами.

Три правила, которые надо знать.

**Отложенные вызовы выполняются в обратном порядке** (стек):

```go
for i := range 3 {
	defer fmt.Println("отложено:", i)
}
```

```
отложено: 2
отложено: 1
отложено: 0
```

Логично: если вы открыли файл, а затем соединение, закрывать надо сначала соединение.

**Аргументы вычисляются в момент объявления `defer`, а не выполнения:**

```go
x := 1
defer fmt.Println("значение при объявлении defer:", x)
defer func() { fmt.Println("значение при выполнении:", x) }()
x = 100
```

```
значение при выполнении: 100
значение при объявлении defer: 1
```

Первый `defer` «сфотографировал» единицу сразу. Второй — замыкание, оно читает переменную в момент вызова. Это частый источник недоумения: если нужно актуальное значение, оборачивайте в функцию.

**`defer` работает на уровне функции, а не блока.** Отложенный внутри цикла вызов выполнится не на каждой итерации, а в конце всей функции. Цикл, открывающий файлы с `defer f.Close()` внутри, будет держать открытыми все файлы сразу. Лечится выносом тела цикла в отдельную функцию.

## `defer` и ошибки закрытия

Тонкость, которую упускают почти все: `f.Close()` тоже возвращает ошибку, и при записи в файл она значима — данные могли не долететь до диска. Написав `defer f.Close()`, вы её теряете.

Здесь и пригождается именованный результат:

```go
func writeReport(name string) (err error) {
	f, err := os.CreateTemp("", name)
	if err != nil {
		return err
	}
	defer func() {
		if cerr := f.Close(); cerr != nil && err == nil {
			err = cerr
		}
	}()

	_, err = f.WriteString("отчёт")
	return err
}
```

Отложенная функция может **изменить** именованный результат уже после `return`. Если основная операция прошла успешно, а закрытие сломалось — вернётся ошибка закрытия.

Для файлов, открытых только на чтение, так заморачиваться не нужно: `defer f.Close()` достаточно.

## Что запомнить

- Тип параметра пишется после имени; подряд идущие параметры одного типа объединяются.
- Функция возвращает несколько значений — отсюда модель «результат и ошибка» вместо исключений.
- Именованные результаты документируют смысл, но «голый» `return` в длинной функции вредит читаемости.
- `nums ...int` принимает переменное число аргументов; `slice...` распаковывает слайс при вызове.
- Функции — значения; замыкание захватывает переменные окружения, время жизни берёт на себя сборщик мусора.
- `defer` откладывает вызов до выхода из функции и срабатывает даже при панике.
- Отложенные вызовы идут в обратном порядке; аргументы вычисляются в момент объявления.
- `defer` привязан к функции, а не к блоку, — внутри цикла это ошибка.
- Отложенная функция может изменить именованный результат — так возвращают ошибку закрытия файла.

## Практика

**1. Результат и ошибка.** Напишите функцию `parseAge(s string) (int, error)`, разбирающую строку в возраст и возвращающую ошибку для некорректного ввода и для отрицательных чисел. Обработайте оба случая через `if` с инструкцией. Готово, когда программа не падает ни на одном вводе.

**2. Переменное число аргументов.** Напишите функцию `average(nums ...float64) float64`, возвращающую среднее. Вызовите её тремя способами: с несколькими аргументами, с распакованным слайсом и без аргументов вообще. Готово, когда третий случай не паникует.

**3. Замыкание.** Напишите генератор `accumulator()`, возвращающий функцию, которая накапливает переданные ей числа и отдаёт текущую сумму. Создайте два независимых накопителя и убедитесь, что они не мешают друг другу. Готово, когда суммы считаются раздельно.

**4. Порядок `defer`.** Напишите функцию с тремя `defer` и вычислением между ними. **До** запуска предскажите порядок вывода. Затем добавьте `defer` с аргументом-переменной, которая меняется после объявления. Готово, когда оба предсказания подтвердились.

**5. `defer` в цикле.** Напишите цикл, открывающий пять временных файлов с `defer` внутри. Убедитесь, что закрываются они все разом в конце. Затем перепишите так, чтобы каждый файл закрывался сразу после обработки. Готово, когда второй вариант не держит лишних дескрипторов.
