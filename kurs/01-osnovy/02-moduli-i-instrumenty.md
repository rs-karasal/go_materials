# 2. Модули и инструменты: `go mod`, `go build`, `gofmt`, `go vet`

> ⏱ **~45 минут** · теория 15 мин · практика 30 мин

В прошлой статье мы запустили один файл. Настоящий проект состоит из десятков файлов и чужих библиотек, и всем этим управляет модульная система Go. Разберём её вместе с инструментами, которые в Go идут из коробки и заменяют целый зоопарк сторонних утилит из других экосистем.

## Модуль

Модуль — единица распространения кода: то, что можно подключить как зависимость. Создаётся одной командой:

```bash
go mod init example.com/tasks
```

Появился файл `go.mod`:

```
module example.com/tasks

go 1.26.3
```

**Имя модуля — это путь импорта.** Если код будет жить на GitHub, имя должно совпадать с адресом репозитория: `github.com/user/tasks`. Для учебных проектов подойдёт любое, но приучайтесь сразу: переименовать модуль позже — значит поправить импорты во всех файлах.

Строка `go 1.26.3` фиксирует версию языка, на которую рассчитан код. Компилятор новее соберёт его без проблем — обратная совместимость в Go возведена в принцип: код, написанный в 2012 году, компилируется сегодня.

## Зависимости

Просто напишите импорт в коде:

```go
import (
	"fmt"

	"github.com/google/uuid"
)
```

и выполните:

```bash
go mod tidy
```

```
go: finding module for package github.com/google/uuid
go: found github.com/google/uuid in github.com/google/uuid v1.6.0
```

`go.mod` пополнился строкой `require github.com/google/uuid v1.6.0`. Рядом появился `go.sum` с криптографическими хешами:

```
github.com/google/uuid v1.6.0 h1:NIvaJDMOsjHA8n1jAhLSgzrAzy1Hgr+hNrb57e+94F0=
```

Разница между файлами:

- **`go.mod`** — какие модули и версии нужны. Редактируется командами `go get` / `go mod tidy`, иногда вручную.
- **`go.sum`** — хеши скачанного. Гарантирует, что версия v1.6.0 у вас и на сервере сборки **побайтно одинакова**, даже если автор попытается подменить тег.

Оба файла коммитятся в репозиторий.

`go mod tidy` — команда на каждый день: она добавляет недостающие зависимости и **убирает лишние**, приводя `go.mod` в соответствие с кодом.

Отдельно про группировку импортов: стандартная библиотека идёт первым блоком, внешние пакеты — вторым, через пустую строку. Это не требование компилятора, а соглашение, которое расставляют инструменты.

## Основные команды

- **`go run .`** — собрать во временный файл и запустить.
- **`go build`** — собрать бинарник в текущей папке.
- **`go install`** — собрать и положить в `$GOPATH/bin`.
- **`go test ./...`** — прогнать тесты во всех пакетах.
- **`go mod tidy`** — привести зависимости в порядок.
- **`go doc fmt.Println`** — документация по символу, не выходя из терминала.

Запись `./...` означает «текущий пакет и все вложенные» — она встретится вам постоянно.

Полезная особенность: **кросс-компиляция из коробки**. Собрать линуксовый бинарник с макбука — две переменные окружения:

```bash
GOOS=linux GOARCH=amd64 go build -o app-linux .
```

Никаких контейнеров и тулчейнов. Для языка, на котором пишут серверные приложения, это экономит массу времени.

## `gofmt` — конец спорам о стиле

Форматирование в Go не обсуждается. Возьмём неряшливый код:

```go
func  bad( ) {
x:=1
fmt.Println( x )
}
```

После `gofmt -w .`:

```go
func bad() {
	x := 1
	fmt.Println(x)
}
```

Отступы табами, пробелы вокруг `:=`, никаких лишних пробелов в скобках. Настроек у `gofmt` нет — принципиально. Один канонический стиль означает, что любой код на Go выглядит знакомо, а на код-ревью обсуждают смысл, а не расстановку скобок.

Команда `gofmt -l .` печатает список файлов, требующих форматирования, — удобно для проверки в CI. В редакторах форматирование обычно включено при сохранении, и это стоит настроить сразу.

## `go vet` — встроенный линтер

Компилятор проверяет типы, `vet` ищет подозрительные конструкции, которые формально корректны:

```go
name := "мир"
fmt.Printf("привет, %d\n", name)
```

```
vet_bad.go:7:28: fmt.Printf format %d has arg name of wrong type string
```

Программа скомпилировалась бы и напечатала мусор. `vet` поймал несоответствие формата и аргумента ещё до запуска.

Что он ещё умеет: находить недостижимый код, ошибки в тегах структур, копирование мьютексов (это опасно — статья 20), потерянные результаты вызовов. Запускается автоматически при `go test`.

Для более глубокого анализа ставят `staticcheck` — он находит на порядок больше проблем, включая неэффективные конструкции и типичные ошибки конкурентности. В рабочих проектах его добавляют в CI обязательно.

## Что запомнить

- Модуль создаётся через `go mod init`, его имя — это путь импорта; для публичного кода имя совпадает с адресом репозитория.
- Зависимость добавляется написанием импорта и командой `go mod tidy`.
- `go.mod` описывает нужные версии, `go.sum` фиксирует хеши; оба коммитятся.
- `./...` означает «текущий пакет и все вложенные».
- Кросс-компиляция делается двумя переменными окружения, без дополнительных инструментов.
- `gofmt` не имеет настроек: стиль в Go один для всех.
- `go vet` ищет корректный, но подозрительный код; для рабочих проектов добавляют `staticcheck`.

## Практика

**1. Первый модуль.** Создайте модуль, напишите программу из двух файлов в одном пакете (второй файл — с функцией, вызываемой из `main`). Соберите и запустите. Готово, когда работает без явного перечисления файлов в команде.

**2. Зависимость.** Подключите любой небольшой крейт — например, `github.com/google/uuid` — и напечатайте сгенерированный идентификатор. Загляните в `go.mod` и `go.sum`. Готово, когда понимаете, что записано в каждом файле.

**3. Уборка.** Удалите использование зависимости из кода, но не трогайте `go.mod`. Выполните `go mod tidy` и посмотрите на разницу. Готово, когда `go.mod` очистился сам.

**4. Форматирование.** Испортите форматирование файла (пробелы, отступы, всё в одну строку) и восстановите через `gofmt -w`. Затем найдите в редакторе настройку «форматировать при сохранении» и включите её. Готово, когда `gofmt -l .` ничего не выводит.

**5. Линтер.** Напишите три конструкции, на которые ругнётся `go vet`: неверный формат в `Printf`, недостижимый код после `return`, потерянный результат функции. Готово, когда есть три сообщения и понимание, почему компилятор их пропустил.
