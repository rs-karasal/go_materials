# 12. `any`, приведение типов и `type switch`

> ⏱ **~40 минут** · теория 15 мин · практика 25 мин

Пустой интерфейс — интерфейс без единого метода, а значит, ему удовлетворяет любой тип. Это аварийный выход из системы типов: он нужен там, где тип действительно неизвестен заранее, и вреден везде, где известен. Разберём инструменты работы с ним и границы применимости.

## `any` — пустой интерфейс

```go
var v any = "текст"
```

`any` — псевдоним для `interface{}`, введённый в Go 1.18. Оба обозначают одно и то же, но `any` читается лучше, и в новом коде пишут его.

Переменная типа `any` может содержать что угодно. Плата — **вы теряете всю информацию о типе**: вызвать метод или сложить с числом нельзя, пока тип не восстановлен.

Где `any` уместен:

- разбор данных неизвестной структуры (JSON произвольной формы);
- функции вроде `fmt.Println`, принимающие что угодно для печати;
- контейнеры до появления дженериков — сейчас это уже плохое решение (статья 16).

Где он вреден: в сигнатурах ваших функций, если тип на самом деле известен. `func Process(data any)` перекладывает проверку типов с компилятора на рантайм — то есть на пользователей.

## Приведение типа

Восстановить конкретный тип можно приведением:

```go
s := v.(string)
```

Если тип не совпал — паника:

```go
var v any = "строка"
n := v.(int)
```

```
panic: interface conversion: interface {} is string, not int
```

Поэтому в реальном коде используют форму «comma ok» — ту же, что и с картами:

```go
s, ok := v.(string)     // текст true
n, ok := v.(int)        // 0 false
```

При неудаче возвращается нулевое значение и `false`, паники нет. Обычно это пишут внутри `if`:

```go
if r, ok := sh.(Rect); ok {
	fmt.Println("это Rect с шириной", r.W)
}
```

Приведение работает не только с `any`, но и с любым интерфейсом: так из общего `Shape` достают конкретный `Rect` — или **другой интерфейс**, что бывает нужнее. Например, проверить, умеет ли переданный `io.Reader` ещё и закрываться: `if c, ok := r.(io.Closer); ok`.

## `type switch`

Когда вариантов несколько, вместо цепочки приведений используют `switch` по типу:

```go
func describe(v any) string {
	switch x := v.(type) {
	case nil:
		return "ничего"
	case int:
		return fmt.Sprintf("целое %d", x*2)
	case string:
		return fmt.Sprintf("строка длиной %d", len(x))
	case []int:
		return fmt.Sprintf("слайс из %d чисел", len(x))
	case Shape:
		return fmt.Sprintf("фигура площадью %.1f", x.Area())
	default:
		return fmt.Sprintf("неизвестный тип %T", x)
	}
}
```

```
ничего
целое 42
строка длиной 12
слайс из 3 чисел
фигура площадью 6.0
неизвестный тип float64
```

Ключевая деталь: в каждой ветви `x` имеет **свой конкретный тип**. В ветви `int` с ним можно делать арифметику, в ветви `string` — звать `len`, в ветви `Shape` — вызывать методы интерфейса. В `default` тип остаётся `any`.

Ещё три вещи:

- **`case nil`** ловит интерфейс без значения — отдельная ветвь, потому что `nil` не соответствует ни одному конкретному типу.
- **Ветви с интерфейсами** проверяются как «реализует ли». Порядок важен: `case error` перед `case Shape` перехватит тип, реализующий оба.
- **`%T`** в `fmt` печатает имя типа — незаменимо в `default` и при отладке.

Обратите внимание на длину строки: `describe("привет")` вернул 12, а не 6, — байты, а не руны, как в статье 8.

## Данные неизвестной формы

Типичное применение `any` — разбор произвольного JSON, где структура заранее не известна:

```go
data := map[string]any{"name": "Алия", "age": 30, "tags": []string{"go"}}
for k, v := range data {
	fmt.Printf("%s -> %v (%T)\n", k, v, v)
}
```

```
name -> Алия (string)
age -> 30 (int)
tags -> [go] ([]string)
```

Работать с такой картой можно, но каждое обращение требует приведения — код быстро обрастает проверками. Поэтому в статье 25 мы разберём правильный путь: описать структуру и позволить `encoding/json` разложить данные по полям. `map[string]any` остаётся для случаев, когда формы данных действительно нет.

## Цена

Значение в интерфейсе — это пара «тип, значение», и при упаковке конкретного типа в `any` часто происходит выделение памяти в куче. В горячем цикле на миллионы итераций разница заметна.

Но главная цена не в производительности, а в том, что **ошибки переезжают из компиляции в рантайм**. Функция с `any` в сигнатуре не может быть проверена компилятором: неверный тип обнаружится у пользователя. Именно поэтому появление дженериков (статья 16) считают одним из главных улучшений языка — они закрывают большинство законных применений `any`.

## Что запомнить

- `any` — псевдоним `interface{}`, подходит любому типу; в новом коде пишут `any`.
- Внутри `any` информация о типе есть, но недоступна, пока тип не восстановлен.
- `v.(T)` паникует при несовпадении; форма `v, ok := v.(T)` — безопасная.
- Приведение работает и к другому интерфейсу — так проверяют дополнительные возможности значения.
- `switch x := v.(type)` даёт в каждой ветви значение нужного типа.
- `case nil` обрабатывает пустой интерфейс; ветви с интерфейсами проверяются по порядку.
- `%T` печатает имя типа.
- `any` переносит проверки в рантайм — используйте его только там, где тип действительно неизвестен.

## Практика

**1. Comma ok.** Заведите переменную `any` и попробуйте привести её к трём типам: верному и двум неверным. Сначала без `ok` (получите панику), затем с `ok`. Готово, когда программа не падает ни на одном приведении.

**2. Своя `describe`.** Напишите функцию, принимающую `any` и возвращающую описание для `int`, `float64`, `string`, `bool`, слайса строк и всего остального. Готово, когда все шесть веток достижимы.

**3. Проверка возможностей.** Напишите функцию, принимающую `any`. Если значение реализует `fmt.Stringer`, используйте его `String()`, иначе печатайте через `%v`. Готово, когда оба пути проверены на разных типах.

**4. Порядок ветвей.** Опишите тип, реализующий два интерфейса, и `type switch` с обеими ветвями. Поменяйте их местами и сравните результат. Готово, когда можете объяснить, какая ветвь выиграет.

**5. Карта неизвестной формы.** Разберите `map[string]any` с вложенной картой и слайсом внутри, напечатав все значения с их типами рекурсивно. Готово, когда обход доходит до вложенных уровней.
