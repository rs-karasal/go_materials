# 16. Дженерики

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Дженерики появились в Go 1.18 — через тринадцать лет после выхода языка. Их долго не добавляли осознанно: авторы боялись сложности, которую те приносят в C++ и Java. В итоге получилась намеренно урезанная версия, закрывающая главную боль — необходимость писать одну и ту же функцию для каждого типа или скатываться в `any`.

## Проблема

До 1.18 функцию суммирования приходилось писать отдельно для `int`, отдельно для `float64` — или принимать `any` и терять проверку типов вместе с производительностью (статья 12).

Обобщённый параметр объявляется в квадратных скобках:

```go
func Sum[T Number](nums []T) T {
	var total T
	for _, n := range nums {
		total += n
	}
	return total
}

fmt.Println(Sum([]int{1, 2, 3}))        // 6
fmt.Println(Sum([]float64{1.5, 2.5}))   // 4
```

Тип выводится из аргумента — писать `Sum[int](...)` обычно не нужно. Указывают его явно, только когда вывести неоткуда.

Обратите внимание на `var total T` — так получают нулевое значение обобщённого типа. Присвоить `0` нельзя: `T` может оказаться строкой.

## Ограничения

`T` без ограничений не умеет ничего — даже сравниваться. Что именно разрешено, задаёт **ограничение** (constraint), и в Go это... обычный интерфейс, расширенный набором типов:

```go
type Number interface {
	~int | ~int64 | ~float64
}
```

Вертикальная черта — объединение: подойдёт любой из перечисленных типов.

**Тильда `~`** означает «этот тип и все, определённые на его основе». Без неё свой тип не пройдёт:

```go
type Celsius float64
Sum([]Celsius{1.5, 2.5})     // работает благодаря ~float64
```

Правило: **почти всегда пишите `~`**. Без тильды ограничение отсекает пользовательские типы, что редко является целью.

Готовые ограничения искать не надо:

- **`any`** — любой тип, без операций;
- **`comparable`** — можно сравнивать через `==` (годится в ключи карты);
- **`cmp.Ordered`** — поддерживает `<`, `>`; включает числа и строки.

```go
func MaxOf[T cmp.Ordered](vals []T) (T, bool) { ... }

MaxOf([]string{"груша", "яблоко"})     // яблоко true
MaxOf([]int{})                         // 0 false
```

Нарушение ограничения ловится при компиляции:

```
mx/main.go:12:6: any does not satisfy int | float64
```

## Чего дженерики в Go не умеют

Важный раздел — он экономит часы попыток.

**Нельзя вызывать методы у типов из объединения:**

```go
type Num interface{ ~int | ~float64 }

func Show[T Num](v T) { fmt.Println(v.String()) }
```

```
nm/main.go:7:39: v.String undefined (type T has no field or method String)
```

Ограничение-объединение даёт только операторы, общие для перечисленных типов. Нужны методы — включите их в интерфейс: `interface{ ~int; String() string }`.

**Нет специализации.** Написать отдельную реализацию для конкретного типа, как в C++, нельзя. Если поведение должно различаться — это `type switch` внутри функции.

**Нет обобщённых методов.** Параметр типа объявляют у типа или у функции, но не у метода:

```go
func (s *Stack[T]) Push(v T)        // так можно — T из типа
func (s *Stack) Map[U any](...)     // так нельзя
```

**Не выводятся типы возвращаемого значения.** Если `U` встречается только в результате, его придётся указать явно.

## Обобщённые типы

Синтаксис тот же:

```go
type Stack[T any] struct{ items []T }

func (s *Stack[T]) Push(v T) { s.items = append(s.items, v) }

func (s *Stack[T]) Pop() (T, bool) {
	var zero T
	if len(s.items) == 0 {
		return zero, false
	}
	v := s.items[len(s.items)-1]
	s.items = s.items[:len(s.items)-1]
	return v, true
}
```

В методах параметр повторяется в получателе: `(s *Stack[T])`.

```go
var st Stack[string]
st.Push("первый")
v, ok := st.Pop()
```

Заметьте: нулевое значение `Stack[string]` сразу работоспособно — принцип из статьи 3 соблюдён и здесь.

## Что появилось в стандартной библиотеке

Главная практическая выгода дженериков для большинства — новые пакеты:

```go
nums := []int{3, 1, 2}
slices.Sort(nums)
slices.Contains(nums, 2)
slices.Max(nums)

slices.Sorted(maps.Keys(m))     // отсортированные ключи карты
```

Пакет `slices` заменил обвязку вокруг `sort` и ручные циклы поиска. `maps` даёт `Keys`, `Values`, `Clone`, `Equal`. Обратите внимание: тот же приём с сортировкой ключей мы писали руками в статье 7 — теперь это одна строка.

## Когда применять

Правило сообщества: **не пишите дженерик, пока не написали одно и то же дважды**.

Хорошие поводы:

- контейнеры (стек, очередь, множество, кэш);
- функции над слайсами и картами: `Map`, `Filter`, `Reduce`;
- функции, отличающиеся только типом (числовые операции).

Плохие поводы:

- «на будущее», когда второй тип не появился;
- замена интерфейса там, где интерфейс подходит.

Последнее стоит развернуть. Дженерик и интерфейс решают разные задачи. **Интерфейс — когда важно поведение**: примите `io.Writer`, и любой пишущий тип подойдёт. **Дженерик — когда важно сохранить тип**: `Stack[User]` возвращает `User`, а не `any`, который придётся приводить. Если вы описываете поведение, начинайте с интерфейса: он в Go идиоматичнее.

## Что запомнить

- Параметр типа объявляется в квадратных скобках и обычно выводится из аргументов.
- `var zero T` — способ получить нулевое значение обобщённого типа.
- Ограничение — интерфейс с перечислением типов через `|`; тильда `~` включает производные типы.
- Готовые ограничения: `any`, `comparable`, `cmp.Ordered`.
- У типов из объединения нельзя вызывать методы, если они не объявлены в ограничении.
- Специализации и обобщённых методов в Go нет.
- Обобщённые типы объявляются так же; в методах параметр повторяется в получателе.
- Пакеты `slices` и `maps` — главная повседневная выгода дженериков.
- Не обобщайте раньше второго повторения; для описания поведения предпочитайте интерфейс.

## Практика

**1. Первая обобщённая функция.** Напишите `Contains[T comparable](s []T, v T) bool`. Проверьте на числах и строках. Готово, когда одна функция обслуживает оба типа.

**2. Тильда.** Напишите функцию с ограничением `int | float64` и попробуйте передать свой тип на основе `int`. Получите ошибку, затем добавьте `~`. Готово, когда понимаете разницу.

**3. Map и Filter.** Реализуйте обе функции над слайсами. С их помощью из слайса пользователей получите имена совершеннолетних. Готово, когда цепочка читается как формулировка задачи.

**4. Обобщённый контейнер.** Реализуйте `Queue[T]` с методами `Enqueue`, `Dequeue` (возвращает значение и признак) и `Len`. Проверьте на двух типах. Готово, когда нулевое значение очереди работоспособно без конструктора.

**5. Дженерик против интерфейса.** Напишите две версии функции подсчёта: одну через `interface{ Area() float64 }`, другую через дженерик с тем же ограничением. Сравните сигнатуры и решите, какая уместнее. Готово, когда можете обосновать выбор.
