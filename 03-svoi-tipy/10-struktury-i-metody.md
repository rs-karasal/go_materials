# 10. Структуры и методы: получатель по значению и по указателю

> ⏱ **~50 минут** · теория 20 мин · практика 30 мин

Структура — основной способ описать предметную область в Go. Классов в языке нет, наследования тоже, но есть методы и встраивание, которые закрывают большинство задач. Ключевой вопрос статьи — выбор между получателем-значением и получателем-указателем: ошибка здесь приводит к коду, который молча ничего не делает.

## Структуры

```go
type User struct {
	Name string
	Age  int
	tags []string
}

u := User{Name: "Алия", Age: 30}
```

Регистр первой буквы поля работает так же, как у функций: `Name` виден снаружи пакета, `tags` — нет.

Создавать можно с именами полей (как выше) или без них — `User{"Алия", 30, nil}`. Второй вариант короче, но ломается при добавлении поля, поэтому в рабочем коде пишут с именами.

Нулевое значение структуры — все поля в своих нулевых значениях:

```go
empty := User{}     // Name: "", Age: 0, tags: nil
```

Структуры **сравнимы**, если сравнимы все поля:

```go
p1 := Point{1, 2}
p2 := Point{1, 2}
fmt.Println(p1 == p2)     // true
```

Но появление слайса, карты или функции ломает это:

```go
// ❌ не компилируется
type T struct{ S []int }
a == b
```

```
nc/main.go:10:14: invalid operation: a == b (struct containing []int cannot be compared)
```

Отсюда и требование к ключам карт из статьи 7 — там нужны именно сравнимые типы.

Структура — **значение**: присваивание создаёт независимую копию.

```go
copyP := p1
copyP.X = 99
fmt.Println(p1.X, copyP.X)     // 1 99
```

## Методы

Метод — функция с получателем, объявленным перед именем:

```go
func (u User) Greet() string {
	return "Привет, " + u.Name
}
```

Особенность Go: метод можно объявить **для любого своего типа**, не только для структуры:

```go
type Weekday int
func (d Weekday) IsWeekend() bool { ... }
```

Это делает типы вроде `Weekday` из статьи 3 полноценными — с поведением, а не только с именем.

Ограничение: метод объявляют только для типа, определённого в **вашем** пакете. Добавить метод к `int` или к чужому типу нельзя — для этого создают свой тип на его основе.

## Значение или указатель

Главная тема статьи. Получатель-значение получает **копию**:

```go
func (c C) IncWrong() { c.N++ }

c := C{}
c.IncWrong()
fmt.Println(c.N)     // 0 — ничего не изменилось
```

Программа скомпилировалась, тест «вроде работает», а счётчик не растёт. Компилятор здесь не помощник, поэтому правило нужно держать в голове.

Получатель-указатель работает с оригиналом:

```go
func (u *User) Birthday() {
	u.Age++
}

u.Birthday()     // Age стал 31
```

Обратите внимание: писать `(&u).Birthday()` не нужно. Если переменная адресуема, Go сам берёт адрес. Обратное тоже верно: метод со значением-получателем вызывается у указателя. Синтаксически разницы нет — и именно поэтому ошибку легко не заметить.

**Правила выбора:**

| Берите указатель | Берите значение |
|---|---|
| метод изменяет получателя | метод только читает |
| структура большая | структура маленькая |
| остальные методы типа уже с указателем | тип неизменяемый по замыслу |

Последний пункт важнее остальных: **не смешивайте получатели в одном типе**. Если хотя бы один метод требует указателя, делайте указателями все — иначе получите путаницу с тем, какие вызовы меняют объект, а какие нет. Это же требование всплывёт в статье про интерфейсы.

## Конструкторы

Специального синтаксиса нет — есть соглашение: функция `NewТип`, возвращающая указатель.

```go
func NewUser(name string, age int) *User {
	return &User{Name: name, Age: age}
}
```

Нужен конструктор не всегда. Если нулевое значение структуры рабочее (принцип из статьи 3), пользователь просто напишет `var b bytes.Buffer`. Конструктор заводят, когда есть что инициализировать: карту в поле, соединение, значения по умолчанию.

## Встраивание вместо наследования

Наследования в Go нет. Есть **встраивание** — поле без имени:

```go
type Address struct {
	City string
	Zip  string
}

type User struct {
	Name string
	Age  int
	Address        // встроено
}

fmt.Println(u.City)     // Алматы — не u.Address.City
```

Поля и методы встроенного типа **продвигаются** наверх: обращаться к ним можно напрямую. При этом `u.Address.City` тоже работает, а конфликт имён разрешается в пользу внешнего типа.

Важно понимать, чем это отличается от наследования. Встраивание — это **композиция**: `User` не является `Address`, он его содержит. Никакого полиморфизма здесь нет, переопределения методов родителя — тоже. Механизм существует ради переиспользования кода, а не ради иерархий.

## Строковое представление

Если у типа есть метод `String() string`, `fmt` использует его при печати:

```go
func (u User) String() string {
	return fmt.Sprintf("%s (%d) из %s", u.Name, u.Age, u.City)
}

fmt.Println(u)     // Алия (31) из Алматы
```

Это первый интерфейс, который вы реализуете, — `fmt.Stringer`. Подробно про интерфейсы — в следующей статье.

Для отладки полезны глаголы `%v` и `%+v`: второй печатает имена полей. Но если у типа есть `String()`, оба вызовут его.

## Что запомнить

- Поля с заглавной буквы экспортируются; литералы пишут с именами полей.
- Структуры сравнимы, если сравнимы все поля; слайс или карта в составе ломают сравнимость.
- Структура — значение: присваивание копирует.
- Метод объявляют для любого своего типа, но только в своём пакете.
- Получатель-значение работает с копией — изменения теряются молча.
- Go сам берёт адрес и разыменовывает при вызове методов, поэтому ошибку не видно синтаксически.
- Не смешивайте получатели-значения и получатели-указатели в одном типе.
- Конструктор `NewТип` нужен, когда есть что инициализировать; иначе достаточно нулевого значения.
- Встраивание — композиция, а не наследование: поля и методы продвигаются, полиморфизма нет.
- Метод `String() string` меняет вид типа при печати.

## Практика

**1. Молчаливая ошибка.** Опишите структуру счётчика и метод инкремента с получателем-значением. Убедитесь, что счётчик не растёт. Почините. Готово, когда понимаете, почему компилятор не помог.

**2. Сравнимость.** Опишите две структуры: одну из чисел и строк, другую с полем-слайсом. Попробуйте сравнить экземпляры обеих. Готово, когда получили ошибку и можете объяснить требование.

**3. Свой тип с методами.** Опишите тип `Temperature float64` с методами `Celsius()`, `Fahrenheit()` и `String()`. Готово, когда `fmt.Println` печатает температуру в читаемом виде.

**4. Конструктор.** Опишите структуру с полем-картой. Создайте её литералом и попробуйте записать в карту — получите панику из статьи 7. Добавьте конструктор. Готово, когда обе версии воспроизведены.

**5. Встраивание.** Опишите `Animal` с методом `Describe()` и `Dog`, встраивающий его. Вызовите метод у `Dog`. Затем объявите у `Dog` метод с тем же именем и проверьте, какой вызовется. Готово, когда понимаете правило разрешения конфликтов.
