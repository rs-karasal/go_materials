# 9. Указатели

> ⏱ **~45 минут** · теория 15 мин · практика 30 мин

Указатели в Go есть, но пугаться не стоит: это сильно упрощённая версия того, что было в C. Арифметики указателей нет, освобождать память вручную не нужно, а вернуть адрес локальной переменной — совершенно нормально. Разберём, зачем они нужны и когда их брать.

## Зачем нужны

Go передаёт аргументы **по значению**: функция получает копию. Значит, изменить переданное она не может:

```go
type Counter struct{ N int }

func incValue(c Counter) { c.N++ }

c := Counter{}
incValue(c)
fmt.Println(c.N)     // 0 — изменилась копия
```

Указатель хранит адрес значения, и через него можно добраться до оригинала:

```go
func incPointer(c *Counter) { c.N++ }

incPointer(&c)
fmt.Println(c.N)     // 1
```

Две операции, которые нужно запомнить:

- **`&x`** — взять адрес переменной;
- **`*p`** — обратиться к значению по адресу (разыменование).

В типе звёздочка означает «указатель на»: `*Counter` — адрес счётчика.

```go
x := 5
p := &x
*p = 100
fmt.Println(x)      // 100
```

## Нулевое значение — `nil`

```go
var np *int
fmt.Println(np == nil)     // true
```

Разыменование `nil`-указателя роняет программу:

```
panic: runtime error: invalid memory address or nil pointer dereference
```

Это самая частая паника в Go. Отсюда правило: **если функция может вернуть `nil`-указатель, проверяйте результат**. Обычно об этом сигнализирует возвращаемая рядом ошибка — получили `err != nil`, к указателю не обращайтесь.

## Автоматическое разыменование

Го избавляет от синтаксического шума: для доступа к полю через указатель звёздочка не нужна.

```go
pc := &Counter{N: 7}
fmt.Println(pc.N)      // не (*pc).N
```

Компилятор подставляет разыменование сам. Обратное тоже работает: у значения можно вызвать метод с указательным получателем — язык автоматически возьмёт адрес. Подробно это разберём в следующей статье.

## Возврат адреса локальной переменной

Код, который в C был бы грубой ошибкой, в Go корректен:

```go
func newCounter() *Counter {
	c := Counter{N: 10}
	return &c
}
```

Компилятор выполняет **escape-анализ**: если адрес переменной «убегает» за пределы функции, значение размещается в куче, а не на стеке. Сборщик мусора освободит его, когда исчезнет последняя ссылка.

Отсюда следствие, важное для понимания языка: **вы не управляете тем, где лежит значение**, и обычно вам это не нужно. Компилятор решает сам, а посмотреть на его решения можно командой `go build -gcflags=-m`.

Есть и встроенная функция `new(T)` — выделяет нулевое значение и возвращает указатель:

```go
n := new(int)
*n = 42
```

На практике её используют редко: `&Counter{N: 10}` короче и позволяет сразу задать поля.

## Чего нет: арифметики указателей

```go
// ❌ не компилируется
p := &x
p = p + 1
```

```
na/main.go:6:6: invalid operation: p + 1 (mismatched types *int and untyped int)
```

Двигать указатель по памяти нельзя. Именно это отсекает целый класс уязвимостей C и делает указатели в Go безопасными: указатель либо `nil`, либо указывает на корректное значение, живое благодаря сборщику мусора.

Обход через `unsafe.Pointer` существует, но нужен в единичных случаях — работе с C-библиотеками и низкоуровневых оптимизациях.

## Когда указатель не нужен

Частая ошибка новичков — ставить звёздочки везде. На деле три типа уже содержат указатель внутри:

- **слайс** — указатель на массив, `len`, `cap`;
- **карта** — указатель на хеш-таблицу;
- **канал** — указатель на структуру канала (статья 18).

```go
func double(s []int) {
	for i := range s {
		s[i] *= 2
	}
}
// nums изменился, хотя указателя нет
```

Писать `*[]int` не нужно — разве что вы собираетесь заменить сам слайс целиком (например, сделать `append` и вернуть новый), но тогда чище вернуть его из функции.

А вот массив — значение, и для его изменения указатель нужен:

```go
func doubleArr(a *[3]int) {
	for i := range a {
		a[i] *= 2
	}
}
```

## Когда брать указатель

Три критерия:

1. **Функция должна изменить аргумент.** Единственный способ.
2. **Значение большое.** Копирование структуры из двадцати полей на каждый вызов стоит дороже, чем передача восьми байт адреса. Для двух-трёх полей копия дешевле.
3. **Нужно отличать «пусто» от «нулевое значение».** `*int` умеет быть `nil`, `int` — нет. Приём используют в конфигурациях и JSON: поле не задано или задано нулём — разные вещи.

Во всех остальных случаях передавайте значение. Копия проще, безопаснее в конкурентном коде и не даёт `nil`-паники.

## Что запомнить

- Go передаёт всё по значению; указатель нужен, чтобы функция могла изменить оригинал.
- `&x` берёт адрес, `*p` разыменовывает; в типе `*T` означает «указатель на T».
- Нулевое значение указателя — `nil`, его разыменование вызывает панику.
- К полям через указатель обращаются без звёздочки — компилятор подставляет её сам.
- Возвращать адрес локальной переменной безопасно: escape-анализ переносит значение в кучу.
- Арифметики указателей нет — это отсекает класс уязвимостей C.
- Слайсы, карты и каналы уже содержат указатель внутри; для них `*` не нужна.
- Указатель берут, чтобы изменить аргумент, избежать копирования большой структуры или отличить «пусто» от нуля.

## Практика

**1. Значение против указателя.** Напишите две функции удвоения числа: принимающую `int` и `*int`. Вызовите обе и объясните разницу. Готово, когда результат предсказан заранее.

**2. Паника на nil.** Объявите указатель на структуру без инициализации и обратитесь к полю. Получите панику. Затем добавьте проверку. Готово, когда программа корректно сообщает об отсутствии значения.

**3. Escape-анализ.** Напишите функцию, возвращающую указатель на локальную структуру. Соберите с `go build -gcflags=-m` и найдите в выводе сообщение про перенос в кучу. Готово, когда нашли строку и понимаете её.

**4. Когда указатель лишний.** Напишите функцию, изменяющую элементы слайса, без указателя, и функцию, изменяющую массив, — с указателем. Объясните, почему в первом случае звёздочка не нужна. Готово, когда обе работают.

**5. Отличить ноль от «не задано».** Опишите структуру настроек с полем `Timeout *int`. Напишите функцию, которая печатает «не задано» для `nil` и значение — иначе, различая случай `0`. Готово, когда три состояния (nil, 0, 30) обрабатываются по-разному.
