# 1. Go: зачем он нужен, установка и первая программа

> ⏱ **~40 минут** · теория 15 мин · практика 25 мин

Go создавался в Google для решения не технической, а организационной проблемы: большие команды тонули в сложности C++ и медленной сборке. Отсюда все его особенности — язык намеренно маленький, компилируется за секунды, а лишних способов сделать одно и то же в нём почти нет. Разберёмся, что это даёт на практике, поставим тулчейн и напишем первую программу.

## Какую задачу решает Go

Три вещи определяют лицо языка.

**Простота как принцип.** В Go нет классов, наследования, исключений, перегрузки операторов и — до недавнего времени — дженериков. Это не упущение, а решение: спецификация языка умещается в один вечер чтения, и весь код в компании выглядит одинаково. Цена — многословность: то, что в Python пишется одной строкой, здесь займёт четыре.

**Скорость сборки и деплоя.** Компиляция занимает секунды даже на больших проектах. Результат — один статический бинарник без зависимостей: скопировали файл на сервер, запустили. Именно поэтому Go стал языком инфраструктуры — Docker, Kubernetes, Terraform написаны на нём.

**Конкурентность в языке, а не в библиотеке.** Горутины и каналы — часть синтаксиса. Запустить сто тысяч конкурентных задач здесь нормально и дёшево, тогда как сто тысяч потоков ОС не выдержит ни одна машина.

Чем платим: сборщик мусора (значит, паузы и не тот уровень контроля, что в Rust или C), многословная обработка ошибок и небогатая система типов.

Практический вывод для вас как для ученика: **Go учится быстро**. Через неделю вы будете писать рабочий код. Сложность здесь не в языке, а в правильном использовании конкурентности — ей посвящена целая часть курса.

## Установка

Скачайте установщик с [go.dev/dl](https://go.dev/dl/) для своей системы. На macOS можно через Homebrew: `brew install go`.

Проверка:

```bash
go version
```

```
go version go1.26.3 darwin/arm64
```

Одна команда `go` содержит всё: компилятор, форматировщик, менеджер зависимостей, тестовый запускатель. Отдельных инструментов ставить не нужно — этим Go выгодно отличается от экосистем, где сборщик, линтер и менеджер пакетов приходится собирать по частям.

## Первая программа

Создайте файл `main.go`:

```go
package main

import "fmt"

func main() {
	fmt.Println("Привет, мир!")
}
```

Запустите:

```bash
go run main.go
```

```
Привет, мир!
```

Разберём по строкам.

**`package main`** — каждый файл принадлежит пакету. Имя `main` особенное: так помечается исполняемая программа. Пакет с другим именем — библиотека, запустить её нельзя.

**`import "fmt"`** — подключение пакета стандартной библиотеки. `fmt` (от *format*) отвечает за ввод-вывод.

**`func main()`** — точка входа. Как и `package main`, имя обязательное.

**`fmt.Println`** — вызов функции из пакета. Заглавная буква в имени не случайна: в Go **регистр определяет видимость**. `Println` экспортирована и доступна снаружи пакета, `println` была бы приватной. Никаких `public` и `private` — только первая буква.

**Табуляция для отступов.** Это не ваш выбор: `gofmt` приведёт код к такому виду принудительно.

## Компилятор со строгим характером

Go — один из самых придирчивых языков в мелочах. Первое, обо что спотыкаются все:

```go
// ❌ не компилируется
import (
	"fmt"
	"os"
)

func main() {
	fmt.Println("привет")
}
```

```
./bad1.go:5:2: "os" imported and not used
```

Неиспользуемый импорт — **ошибка**, а не предупреждение. То же с переменными:

```go
// ❌ не компилируется
count := 5
fmt.Println("привет")
```

```
./bad2.go:6:2: declared and not used: count
```

Поначалу это бесит: закомментировали строку для отладки — программа перестала собираться. Замысел в другом: мёртвый код не накапливается, а импорты не превращаются в свалку. В команде из полусотни человек это заметно экономит время.

Есть и совсем неожиданное правило:

```go
// ❌ не компилируется
func main()
{
	fmt.Println("привет")
}
```

```
./brace.go:6:1: syntax error: unexpected semicolon or newline before {
```

Открывающая скобка **обязана** стоять на той же строке. Причина техническая: Go автоматически вставляет точки с запятой в конце строк, и перенос скобки ломает разбор. Спорить о стиле оформления в Go не о чем — вариант ровно один.

## Бинарник

`go run` компилирует во временный файл и запускает. Для настоящей сборки сначала создают модуль:

```bash
go mod init example.com/hello
go build -o hello .
./hello
```

Получился исполняемый файл на 2,5 МБ — крупноват для «Привет, мир», потому что внутри лежит рантайм языка со сборщиком мусора и планировщиком горутин. Взамен файл **самодостаточен**: он не требует ни установленного Go, ни библиотек, ни интерпретатора. Скопировали на сервер — работает.

Что такое модуль и зачем `go mod init` — тема следующей статьи.

## Что запомнить

- Go создавался ради простоты, быстрой сборки и встроенной конкурентности; платой стали многословность и небогатая система типов.
- Одна команда `go` заменяет компилятор, форматировщик, линтер и менеджер пакетов.
- `package main` и `func main()` — обязательная пара для исполняемой программы.
- Регистр первой буквы определяет видимость: `Println` экспортирована, `println` — нет.
- Неиспользуемый импорт или переменная — ошибка компиляции, а не предупреждение.
- Открывающая фигурная скобка всегда на той же строке — иначе синтаксическая ошибка.
- `go run` запускает, `go build` собирает самодостаточный бинарник с рантаймом внутри.

## Практика

**1. Проверка окружения.** Установите Go и выведите версию. Запустите `go help` и найдите в списке команды `run`, `build`, `fmt`, `test`, `vet`. Готово, когда знаете, за что отвечает каждая.

**2. Своё приветствие.** Измените программу так, чтобы она печатала три строки: приветствие, текущий год и название языка. Готово, когда программа печатает ровно три строки.

**3. Коллекция ошибок.** Сломайте программу четырьмя способами: неиспользуемый импорт, неиспользуемая переменная, скобка на новой строке, вызов `fmt.println` с маленькой буквы. Запишите текст каждой ошибки. Готово, когда есть табличка «что сломал → что ответил компилятор».

**4. Run против build.** Соберите программу через `go build` и запустите бинарник напрямую. Сравните размер файла с исходником. Готово, когда можете объяснить разницу в размере.

**5. Чтение документации.** Выполните `go doc fmt.Println`, затем `go doc fmt`. Найдите функцию, которая печатает **без** перевода строки, и функцию, которая форматирует строку по шаблону. Используйте обе. Готово, когда программа печатает `Привет, Go!` тремя разными способами.
